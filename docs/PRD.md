# 「면접 재판정」서비스 기획안

---

## 1. 서비스 개요

- **서비스명(가안)**: 재판정 / Judge Me / 서류합의체
- **정의**: 품앗이 구조 기반 자소서·이력서 크라우드 심사 플랫폼
- **핵심 가치제안**: 남을 평가해야 나도 평가받는 구조를 통해, 무료에 가까운 비용으로 동일 직군 다수의 "현실적 합의 피드백" 제공
- **플랫폼 형태**: 웹 기반 (모바일 앱 아님)

### 1-1. 기존 서비스 대비 포지셔닝


| 구분    | AI 첨삭 (챗GPT 등) | 유료 1인 첨삭 (잡코리아 등) | 재판정        |
| ----- | -------------- | ----------------- | ---------- |
| 비용    | 무료~저가          | 고가                | 크레딧(품앗이)   |
| 현실 감각 | 낮음             | 높음 (편향 가능)        | 높음 (다수 합의) |
| 개성 반영 | 낮음(정답화 경향)     | 중간                | 높음         |
| 평가자 수 | -              | 1인                | 다수(매칭 인원)  |


---

## 2. 핵심 메커니즘

### 2-1. 품앗이 크레딧 구조

- 타인 자소서 1건 평가 시 크레딧 1점 획득
- 본인 자소서 1건 등록 시 크레딧 3점 소모(평가자 3인 매칭)
- 크레딧 미보유 시 등록 불가 처리 → 평가 참여를 구조적으로 강제

### 2-2. 매칭 로직

- 직군(마케팅/개발/디자인 등) 및 연차(신입/경력) 태그 기반 매칭
- 평가자는 동일 직군 지원 경험자 또는 현직자로 한정 → 무분별한 평가 진입 차단

### 2-3. 평가 방식

- 정량 평가 필수: 직무적합성 / 논리구조 / 구체성(숫자·사례) / 가독성, 4개 항목 5점 척도
- 정성 코멘트 최소 50자 이상 필수 입력

## 3. 신뢰도 시스템 (핵심 재설계)

### 3-1. 설계 배경 및 문제의식

- 기존 안: 서류 합격 여부 사후 확인을 통한 안목 레벨 측정
- 한계: 합격 여부는 사용자의 추가 액션(자진 갱신)이 필요하여 입력률 저조 예상, 결과 확인까지 시차(수 주~수개월) 발생으로 즉시 반영 불가
- 대안 검토: 제출자의 즉시 피드백 만족도로 대체하는 방안 검토
- **비판적 검토 결과**: 즉시 만족도는 "듣기 좋은 평가"와 "정확한 평가"를 구분하지 못함. 날카롭고 정확한 지적일수록 당장은 낮은 점수를 받을 가능성이 있어, 이 지표를 그대로 안목 레벨에 반영할 경우 평가자가 진실보다 듣기 좋은 말을 하도록 인센티브가 왜곡될 위험 존재
- 아울러 신입/취준생 다수인 제출자가 전문성 있는 지적을 그 자리에서 정확히 판단할 능력에 한계가 있다는 점도 고려 필요

### 3-2. 최종 설계안: 지표 이원화


| 지표         | 측정 시점   | 측정 방식               | 용도                        |
| ---------- | ------- | ------------------- | ------------------------- |
| **신뢰 점수**  | 즉시      | 제출자의 구조화된 체크리스트 응답  | 매칭 큐 노출 순서, 초기 진입장벽 산정    |
| **정확도 점수** | 지연(검증됨) | 합격 여부 등 사후 결과와의 일치도 | "검증된 안목" 뱃지 등 상위 신뢰 지표 부여 |


- 정확도 점수가 낮게 확인된 평가자는 이후 신뢰 점수 가중치를 하향 조정하는 보정 구조 적용
- 즉시성과 정확성이라는 상반된 요구를 층위 분리로 동시 충족

### 3-3. 즉시 신뢰 점수 질문 설계 원칙

- "도움이 되었나요?" 등 포괄적 만족도 질문 배제
- 행동 기반 사실 질문으로 대체
  - 구체적 사례·숫자를 지적하였는가 (예/아니오)
  - 제출자가 미처 생각하지 못한 관점을 제시하였는가 (예/아니오)
  - 실행 가능한 대안을 제시하였는가 (예/아니오)
- 감정적 만족도가 아닌 피드백의 구조적 특성을 측정하는 방향으로 설계

## 4. MVP 기능 범위


| 기능              | MVP 포함 여부 | 비고                       |
| --------------- | --------- | ------------------------ |
| 회원가입 및 직군·연차 태깅 | 필수        | 최소 정보만 수집                |
| 자소서 등록(텍스트)     | 필수        | 파일 업로드는 후순위              |
| 크레딧 시스템         | 필수        | 서비스 근간                   |
| 평가 매칭 큐         | 필수        | 초기 FIFO + 태그 필터          |
| 4축 정량평가 및 코멘트   | 필수        |                          |
| 즉시 신뢰 점수(체크리스트) | 필수        | 3-3 항목 질문 적용             |
| 정확도 점수(사후검증)    | 후순위       | 합격 여부 입력 데이터 축적 이후 v2 반영 |
| 실시간 알림          | 후순위       | 이메일 다이제스트로 대체            |
| AI 성의없음 필터      | 후순위       | 초기엔 신고 기능으로 대체           |


- MVP 핵심 검증 가설: 품앗이 구조가 실제로 작동하는가(크레딧 획득을 위해 성실한 평가가 이루어지는가)

## 7. 향후 검토 과제

- 초기 시딩 대상 직군 1개 확정 및 랜딩페이지 카피 설계
- MVP 기술 스택 및 DB 구조(크레딧 원장, 신뢰 점수·정확도 점수 필드 분리 설계 포함) 구체화
- 정확도 점수 산정을 위한 사후 결과 입력 UX 설계
